# Бандл проверок «Комфорт» (`tormozit.comfort.checks`)

## Зачем отдельный бандл

EDT хранит в базе модели проекта версию **каждого бандла-поставщика проверок** и список его проверок (`ProjectCheckMetadataManager`). При открытии проекта версии сравниваются (`Version.equals`, **с квалификатором**), и если версия изменилась, все проверки этого поставщика попадают в `updated`, после чего EDT зовёт

```text
ICheckScheduler.scheduleValidation(проект, эти_проверки, <пустой набор объектов>)
```

Пустой набор объектов — перепроверка **всего проекта**. Одна из наших проверок работает по модулям, поэтому такая перепроверка на большой конфигурации идёт десятки минут и заметно тормозит машину.

Версия основного бандла `tormozit.comfort` меняется **каждой сборкой** (`site/scripts/sync-version.ps1` штампует `Bundle-Version` квалификатором сборки). Пока проверки жили в нём, каждая новая версия «Комфорта» означала полную перепроверку конфигурации при следующем запуске EDT.

Здесь версия фиксированная и скриптом синхронизации **не трогается** — обновления «Комфорта» перепроверку больше не вызывают.

## Правило: версию поднимать вручную

**Меняешь логику существующей проверки — подними `Bundle-Version` в `META-INF/MANIFEST.MF`** (третий разряд: `1.0.0` → `1.0.1`). Иначе EDT не узнает об изменении и оставит замечания, посчитанные старой логикой, до ближайшей правки самих модулей.

Когда поднимать **не нужно**:

- добавлена новая проверка или удалена существующая — EDT видит это по составу id проверок, независимо от версии;
- правка только в комментариях, текстах, форматировании — результат проверки не меняется.

Страховка, если всё-таки забыли: команда «Проверить» на корневом узле проекта в навигаторе (`ComfortCheckRecompute.recomputeProject`) запускает полную перепроверку всеми проверками, не глядя на версии бандлов.

## Что где лежит

- Классы проверок — `src/tormozit/checks/`.
- Идентификаторы проверок — в основном бандле, `tormozit.ComfortCheckIds`: на них ссылаются хуки основного бандла, а зависеть от бандла проверок он не может (кольцо зависимостей).
- Регистрация в EDT — `plugin.xml` этого бандла; в `plugin/plugin.xml` их быть не должно.
