# Аудит вплетений EDT

После сборки обоих бандлов в PDE запустите из корня репозитория.

```powershell
.\site\scripts\run-weaving-audit.ps1
```

Команда читает `bundles.info` установок EDT 2026.1 и 2026.2 из 1C:EDT Start. Для старта используются классы из `plugin.early\bin` и `plugin\bin`. Параметры `-Early` и `-Main` принимают каталоги классов или JAR.

Для других установок передайте список профилей и профиль зависимостей, совместимый с Java 17.

```powershell
$profiles = @($profile2026_1, $profile2026_2)
.\site\scripts\run-weaving-audit.ps1 -Profiles $profiles -DependencyProfile $profile2026_1
```

Подставьте в переменные полные пути к `bundles.info` каждой установки. `-JavaHome` задаёт каталог JDK 17.

На каждый профиль записывается отдельный `audit.log` в `.tmp/weaving-audit/`. Для каждого совпадения выводятся версия бандла, класс и изменившиеся методы с JVM-сигнатурами. Отсутствующая либо неоднозначная цель, пропущенное вплетение или ошибка проверки ASM дают код выхода 1. Отдельный Java-процесс на профиль изолирует состояние обработчиков и их временную диагностику.

## Как добавлять цели

В [targets.tsv](targets.tsv) каждая строка задаёт этап (`early` или `main`), символическое имя бандла, имя класса и полное имя обработчика. При переносе класса в пределах бандла перечислите варианты через `|`. В каждой проверяемой версии должен находиться ровно один из них. При добавлении цели в существующий обработчик добавьте отдельную строку.

Проверки сигнатур, инструкций и числа точек изменения остаются рядом с преобразованием в Java. Если новый релиз меняет только форму байткода, добавьте проверенный вариант в тот же обработчик и прогоните обе версии. Отчёт показывает результаты преобразований классов на диске. Порядок загрузки классов и поведение функций после вставки проверяются в запущенной EDT.
