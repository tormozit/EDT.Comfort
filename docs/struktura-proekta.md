# Структура проекта

Представление **Структура проекта** (дерево файлов проекта в Eclipse, `Project Explorer`).

## Фильтр по подстроке

Над деревом — поле [иерархического фильтра](obshchie-mekhanizmy.md#filtry-po-podstroke-v-spiskah) ([#290](https://github.com/tormozit/EDT.Comfort/issues/290)), как в навигаторе: точка делит запрос на секции «родитель.узел» (например `спр.анкет` находит справочники с «анкет» в имени). Точка **в имени файла** (любое расширение) иерархию не делит: `прав.RecordSetModule` находит `RecordSetModule.bsl` под папкой с «прав». В кавычках — точная фраза целиком (`"RecordSetModule.bsl"`). Ищет по имени файла или папки и **русскому названию типа** из декоратора папок-групп (например «Справочники» для `Catalogs`). Обезличенный суффикс **`<объект>`** в фильтре не участвует. В дереве остаются только совпавшие узлы и их родители. Совпадения подсвечиваются; история запросов сохраняется (**Ctrl+↓**). Настройка: **Параметры → Комфорт → Улучшать списки**.

## Индикаторы связи папок с объектами

Для папок, в которых есть файл **`.mdo`**, к подписи добавляется суффикс ([#237](https://github.com/tormozit/EDT.Comfort/issues/237)):

| Суффикс | Значение |
|---------|----------|
| ` <объект>` | Объект **привязан** к конфигурации — его полное имя встречается в `Configuration.mdo` |
| ` <?>` | Файл mdo **есть на диске**, но объекта **нет** в конфигурации («осиротевший» объект) |

Папки без mdo-файла не декорируются. Для групповых папок без своего mdo (Catalogs, Forms, Documents и т.п.) выводится русское мн.ч. типа метаданных.

Сценарий «осиротевшего» mdo — см. [Git: восстановление и Configuration.mdo](git-izmeneniya.md#osirotevshij-mdo).

## Поиск недостижимых файлов метаданных :id=nedostizhimye-fajly

Папка объекта, которого нет в составе конфигурации, — «наполовину» существующий объект: в навигаторе его нет, но сравнение конфигураций его файлы учитывает, и добавить такой объект объединением нельзя. Для этого достаточно одного любого файла в папке, не обязательно mdo ([#754](https://github.com/tormozit/EDT.Comfort/issues/754)).

Команда **«Комфорт → Найти недостижимые файлы метаданных»** в контекстном меню этой панели и [навигатора](navigator.md) обходит непустые папки внутри папок выбранных узлов и показывает недостижимые в панели **«Поиск»** в режиме **«Недостижимые файлы»**. Объект верхнего уровня считается недостижимым, если его нет в `Configuration.mdo`; форма, макет и команда — если их нет в mdo объекта-владельца. Папки внутри недостижимой отдельно не показываются. На узле проекта или конфигурации проверяется вся папка `src`.

Колонки результата: **«Путь»** — полное имя объекта метаданных со значком его вида, **«Папка»**, **«Тип»**. Двойной щелчок или команда **«Показать в структуре проекта»** выделяет папку в этой панели. Команда **«Открыть объект»** открывает редактор объекта строки. Команда **«Подключить к родителю»** прописывает объекты выделенных строк у родителя: объект, в папке которого есть mdo-файл, — в `Configuration.mdo`, форму (с файлом `Form.form`) и макет — в mdo объекта-владельца; вид макета определяется по его файлу. Команды и папки без mdo-файла она пропускает. Подключённые строки из результата убираются, после чего открывается редактор подключённого объекта и объект показывается в навигаторе (из нескольких подключённых — первый).

Та же проверка выполняется [перед фиксацией, заменой на HEAD-ревизию и удалением файла](git-izmeneniya.md#nedostizhimye-fajly-git).

Автопроверка **«Достижимость объекта метаданных»** ([проверки Комфорт](proverki-konfiguracii.md#proverki-komfort)) помечает объект верхнего уровня, которого нет в составе конфигурации; её быстрое исправление **«Подключить к конфигурации»** действует так же, как команда **«Подключить к родителю»**. Папки без mdo-файла, формы, макеты и команды автопроверка не находит — для них остаётся команда поиска.

При любом запуске сравнения конфигураций (мастер **«Сравнить/объединить»**, сравнение и объединение из Git) проекты рабочей области, участвующие в сравнении, проверяются параллельно с ним. Сравнение не задерживается: если недостижимые папки найдены, они показываются в панели **«Поиск»** и появляется уведомление. Проверка отключается флажком [**«Контролировать ссылки метаданных в ключевых операциях»**](nastroyki.md#kontrol-ssylok).

## Команды в подменю «Комфорт»

В контекстном меню дерева — подменю **Комфорт** ([#238](https://github.com/tormozit/EDT.Comfort/issues/238)):

| Действие | Клавиши | Описание |
|----------|---------|----------|
| Открыть объект | F2 | Открыть объект метаданных выбранного файла/папки в редакторе EDT |
| Показать в навигаторе | Ctrl+T | Выделить соответствующий объект в [навигаторе](navigator.md) |
| Найти недостижимые файлы метаданных | — | [Найти папки объектов, не связанные с конфигурацией](#nedostizhimye-fajly); доступна для любых выбранных ресурсов |
| Свернуть все другие | — | Свернуть все ветки, кроме родителей текущего выделения ([общие механизмы](obshchie-mekhanizmy.md#svernut-vse-drugie)) |

Команды доступны, если для выбранного ресурса удаётся определить объект метаданных (аналогично [Git-панелям](git-izmeneniya.md)).

## Копирование имён (Ctrl+C)

**Ctrl+C** при выделении одного или нескольких элементов дополнительно кладёт в буфер **имена** файлов/папок (по одному на строку) — удобно для вставки в сторонние приложения ([#235](https://github.com/tormozit/EDT.Comfort/issues/235)). Подробнее — [Навигатор → Копирование имён](navigator.md#kopirovanie-imyon).
