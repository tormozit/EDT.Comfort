# Расчет типов

Доработки расчёта типов встроенного языка BSL: документирующие комментарии, ссылки `см. …`, тип формы. Влияют на автодополнение после точки, подсказки и проверку типов — не только на вид popup.

Связанный раздел: [Автодополнение](avtodopolnenie.md).

## Несколько типов через запятую в комментарии

Если на **одной строке** в `// Параметры:` или `// Возвращаемое значение:` указано несколько типов через запятую, после точки доступны свойства и методы **всех** этих типов. В автодополнении **Родитель:** показывает оба имени. Следующие строки (поля структуры и т.п.) в этот список не входят.

```
// Параметры:
//  Форма - РасширениеФормыКлиентскогоПриложенияДляДинамическогоСписка, ФормаКлиентскогоПриложения - комментарий
Процедура ФормаСпискаПриСозданииНаСервере(Знач Форма) Экспорт
```

```
// Возвращаемое значение:
//  Структура, Соответствие - комментарий
Функция Данные() Экспорт
```

После `Форма.` доступны и члены формы (`Элементы`, `Команды`, …), и члены расширения динамического списка (`Список`, …). Дальше по цепочке (`Форма.Элементы.`) тип тоже считается. Работает всегда, в том числе при выключенном **Улучшать списки**.

## Начальное значение неявной переменной

Для локальных переменных, введённых присваиванием без `Перем`, учитывается начальное значение `Неопределено`. Если после условного присваивания остаётся путь без присваивания, состав типов включает `Неопределено` вместе с типом присвоенного значения. После безусловного присваивания начальное `Неопределено` в состав не входит. Это учитывается в подсказках при наведении и в автодополнении независимо от флажка **Расширенный расчет типов**.

## Расширенный расчет типов :id=extended-types

Флажок **Расширенный расчет типов** (параметры проекта → Комфорт) включает несколько доработок расчёта типов встроенного языка. Пока он установлен, штатный флажок EDT **Перезаписывать типы документирующим комментарием** (свойства проекта → Встроенный язык) удерживается включённым: расширенный расчёт строится поверх этого режима.

### Документирующий тип объединяется с рассчитанным

Тип из документирующего комментария дополняется типом, рассчитанным по коду. Это же работает для ссылки **см. Метод**: если у метода, на который она указывает, своего документирующего комментария нет, тип берётся из его кода — без флажка список после такой ссылки оставался пустым.

Знаки в начале описания типа управляют объединением поштучно: `%` — не приливать рассчитанный тип, `^` — прилить обязательно. Например `^, Массив`.

### Тип свойства структуры и колонки таблицы значений

Тип свойства структуры задаётся комментарием в конце строки, где свойство добавляется:

```bsl
Ног = Новый Структура;
Ног.Вставить("Бобр"); // Массив
Ног.Бобр.Добавить(1);
```

Без комментария EDT знает имя свойства `Бобр`, но не знает его тип: значение в `Вставить` не передано, брать тип неоткуда. С комментарием после `Ног.Бобр.` доступны члены массива, и тип считается дальше по цепочке.

Так же типизируется колонка таблицы (дерева) значений — тип получает **значение** колонки в строке:

```bsl
ТЗ = Новый ТаблицаЗначений;
ТЗ.Колонки.Добавить("Бобр"); // Структура
Для Каждого Строка Из ТЗ Цикл
    Строка.Бобр.Вставить("Дегул", 1);
КонецЦикла;
```

Правила записи типов те же, что в документирующем комментарии: русское или английское имя типа, несколько типов через запятую, ссылка `см. Метод`. Тип из комментария **дополняет** вычисленный, а не заменяет его: в `Ног.Вставить("Бобр", Неопределено); // Массив` у свойства будут оба типа.

После типов через `-` можно указать описание свойства. Оно показывается в подсказке автодополнения и при наведении, а также в описании рассчитанного результата функции. Если тип берётся из переданного значения, комментарий можно начать сразу с `-`:

```bsl
Параметры.Вставить("ВключитьКонтрольВеденияУчета", Ложь); // - для списка
Параметры.Вставить("РеквизитыСЧасовымиПоясами", Неопределено); // Соответствие, Неопределено - полные имена реквизитов
```

### Ссылка «см. …» рядом с другим типом или описанием

В списке типов EDT видит ссылку `см. …` только тогда, когда та занимает весь список целиком. Достаточно дописать после неё описание или второй тип — и ссылка перестаёт распознаваться: тип не вычисляется, подсказка при вводе имени типа после «см.» не появляется.

```bsl
// Параметры:
//   Форма - см. Обработка.Обработка1.Форма.Форма1, РасширениеФормыКлиентскогоПриложенияДляДокумента - описание
```

Плагин распознаёт ссылку в любом месте списка типов — и рядом с другими типами, и когда за списком следует описание. Так же работает секция возвращаемого значения.

Кроме того, EDT считает ссылкой весь остаток строки после «см.», поэтому за запятой не предлагала имена типов. Плагин ограничивает ссылку её собственным текстом: внутри ссылки работает подсказка ссылки, после запятой — подсказка имён типов.

### Тип формы: экспорт модуля

Когда параметр, переменная или результат вызова типизированы конкретной формой — ссылкой `см. ОбщаяФорма.…` / `см. Справочник.…Форма.…` либо `ПолучитьФорму`/`ОткрытьФорму` со строковым именем формы — после точки доступны не только реквизиты и элементы формы, но и **экспортные** процедуры и переменные модуля этой формы (`&НаКлиенте` / `&НаСервере` с `Экспорт`).

```bsl
// Параметры:
//   Форма - см. ОбщаяФорма.Форма1
Функция Пример(Форма) Экспорт
    Форма.МойЭкспортныйМетод();
```

Без флажка экспорт модуля в такой тип не входит. Реквизиты формы после `ПолучитьФорму("…").` видны и при выключенном флажке.

### Поля результата запроса

При включённом флажке **Расширенный расчет типов** в открытом модуле рассчитываются имена и типы полей выборки (`Выполнить().Выбрать()`) и строк выгруженной таблицы (`Выполнить().Выгрузить()`). Текст должен быть отдельным строковым литералом в конструкторе `Новый Запрос("…")` или в присваивании `Запрос.Текст = "…"`.

Поддерживается `ВыполнитьПакет()`: постоянный индекс массива результатов (`[0]`, `[1]` или `Получить(0)`) выбирает соответствующий запрос пакета. Промежуточные переменные результата, выборки и таблицы поддерживаются, когда их присваивание однозначно определяется в текущем методе. Конкатенация, получение текста из переменной, функции или макета пока не рассчитываются.

Команда перехода к определению и Ctrl+клик на поле выборки или строки таблицы ведут внутрь текста запроса: на псевдоним после `КАК`, а без псевдонима — на имя поля или выражение. Ссылки на поле в подсказке при наведении и в боковой подсказке автодополнения ведут туда же.

Расчёт выполняется при запросе автодополнения, подсказки при наведении или перехода к определению в том же фоновом потоке, что и досчёт типов метода. Для запросов с ошибками сохраняется штатное поведение EDT. Поля результата создания временной таблицы отдельно не рассчитываются.

Автопроверка **«Неизвестное поле результата запроса»** в категории **«Комфорт»** отмечает обращения к отсутствующим полям выборки. Она работает при включённом флажке **Расширенный расчет типов** и использует общий с подсказками расчёт схемы. Если валидация выполняется первой, она подготавливает план для текущей версии метода; последующий запрос подсказки переиспользует его. Важность замечания и подавление настраиваются штатными средствами EDT.

Быстрое исправление в подсказке ошибки и по Ctrl+1 предлагает заменить опечатку на ближайшее по расстоянию Левенштейна имя поля этой выборки. Например, для `Выборка.Кратность2` предлагается `Кратность`. Список полей берётся из уже рассчитанного плана запроса.

Проверка пропускает запросы с ошибками, неоднозначные присваивания и обращения к строкам выгруженной таблицы значений: её колонки могут изменяться после выполнения запроса.
