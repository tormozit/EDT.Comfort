# Бандл хука разбора BSL (`tormozit.comfort.bslparser`)

## Зачем отдельный бандл

Хук исправляет разбор модулей, где директива `#Если` (а также `#Вставка`/`#Удаление`) разрывает оператор (issue #561, описание — в javadoc `BslParserHook`). Для этого он вплетается через OSGi `WeavingHook` в классы парсера EDT (`BslParser`, `CustomBslParser`, `BslPartialParsingHelper`).

Скрытые директивы — листья `SL_COMMENT` без `//`. Штатный `BslSuppressionProvider.extractSuppressions` отрезает `//` от любого такого листа и падал на односимвольном (скобка в условии `#Если Не (…) Тогда`), обрывая валидацию модуля. Поэтому в него тоже вплетена подмена: текст не на `//` он видит как пустой комментарий `//`.

`WeavingHook` видит только классы, загруженные **после** его регистрации. Парсер BSL загружается при открытии проектов, а основной бандл Комфорта активируется лениво и позже. Хук, зарегистрированный из `tormozit.Activator`, не вплёлся ни в один класс (проверено по временному логу 26.09.2026), а агент с перезагрузкой классов в EDT недоступен.

Поэтому хук живёт в отдельном маленьком бандле, который **стартует вместе с фреймворком**, до приложения:

- в установленном плагине — `META-INF/p2.inf` (`setStartLevel(4)` + `markStarted(true)`);
- в PDE-запуске — запись `tormozit.comfort.bslparser,…,4,true` в `bundles.info` профиля. Её ставит `site/scripts/comfort-osgi-version.ps1` (`sync-version.ps1`, `restore-main.ps1`, `assert-comfort-osgi.ps1 -Repair`).

## Правила

- **Не зависеть от основного бандла.** Обращение к его классам активировало бы весь Комфорт на старте фреймворка, до Workbench.
- **`Activator` не касается типов Xtext** — иначе ранний старт активирует бандл Xtext. Классы Xtext грузит `BslParserHook`, при первом разборе.
- Нет `Bundle-ActivationPolicy: lazy`: ленивый бандл даже с флагом «запущен» активируется только при первой загрузке класса.
- Временный лог — `TempLog`: до старта Комфорта строки копятся в памяти, потом уходят в `Global.tempLog` (приёмник кладёт `tormozit.Activator` в системное свойство `tormozit.comfort.tempLog`).
- Версия — `1.0.0.qualifier`: проверок EDT здесь нет, поэтому квалификатор сборки перепроверку проекта не вызывает (в отличие от `plugin.checks`).
